# Session fields

Keep these named fields in the private `session.md`. Use readable headings
and tables; store enough evidence to resume without replaying the interview.

## Context

- Session name, created/updated dates and current stage.
- Tax year and exact dates; provisional or confirmed year.
- Individual return ownership, original/amendment status and residence facts.
- Filing result and reason, selected service/route, registration/access tasks.
- Verified deadlines and separately assessed digital-reporting obligations.
- Next question, last stage summary and the user's confirmation or correction.

## Sections

Give each income source a stable name and record why its section is included,
which records are available, missing items, dependencies and status.

Use these statuses consistently:

| Status | Use when | Next action |
|---|---|---|
| needs information | A fact, document or source check is missing | Name and obtain the missing input |
| needs explanation | The user does not understand an entry or choice | Explain it and ask again |
| needs specialist review | Applicable guidance has not resolved the treatment | Record the precise question and obtain a supported resolution |
| ready for user review | Evidence and checks support the proposed entry | Show it and ask for confirmation |
| confirmed | The user understands and agrees with the supported entry | Include it in whole-return checks |

An initial unreviewed section is needs information. Stage confirmation means
the user agrees with the summary; it does not upgrade unresolved entries.

## Entries

For each applicable field, record:

- Entry name, source name, section, tax year and exact official field label.
- Paper form/box reference and separately verified service label, if available.
- Proposed value or answer, status and user confirmation.
- Source record and precise figure reference; user-entered figures are allowed.
- Applicable official URL, passage/box, local source path and review date.
- Inputs, calculation working, rounding and other field-specific checks.
- Assumptions, chosen claims, disclosures and provisional treatment, if any.
- Earlier answers and entries this field depends on.

Keep fictional examples outside this register. Leave unknown values explicitly
unknown; record a confirmed exclusion with its reason rather than deleting it.

## Review and open items

Record whole-return checks and calculation source, totals, remaining balance,
advance payments and discrepancies separately. For each unresolved item, save
the affected entries, required answer/evidence, next action and who supplies it.

Keep a source register with tax-year applicability and review dates. A changed
year, route, source or underlying fact reopens affected checks and confirmations.

## Change history and deliverables

Record changed facts, previous values, reason, affected entries and renewed
confirmations. Preserve submitted snapshots; give an amendment its own version.

Record guide path, version, status and user approval. Keep service transfer,
calculation comparison, submission evidence and payment status separate; start
submission and payment as not confirmed, never infer either from guide approval.

## Save and resume

For a new session, create a unique folder under `private/self-assessment/`
using the date and a suffix if needed; never overwrite another session. Keep
taxpayer facts there, outside shared sources and skills, and do not commit them.

For a resumed session, read the supplied file or list session names and ask
which to resume if ambiguous. Summarise the saved year, completed sections and
next question; recheck sources whose applicability or currency is uncertain.

Save after each answer, preserving earlier evidence and confirmation history.
On pause, show the path, unresolved items and next question; on resume, read
this file and reopen only checks affected by changed facts or source validity.

When an answer changes, preserve its prior value and reopen dependent entries,
section choices, claims, calculations and the guide for renewed confirmation.
Tell the user the saved path after the first save and at each checkpoint.

If file writing is unavailable, provide these same fields as a copyable
checkpoint and state that no file was saved.
